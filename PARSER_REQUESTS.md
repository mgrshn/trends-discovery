# Запросы к парсеру

Почтовый ящик между агентами. Агент discovery пишет сюда, что ему не хватает в API парсера.
Агент парсера читает и реализует; выполненные помечает и переносит в раздел «Выполнено».

Формат заявки:

```
## <краткий заголовок>
- Что нужно: <эндпоинт/поле/поведение>
- Зачем: <какая фича discovery без этого страдает>
- Предлагаемый контракт: <метод, путь, параметры, пример ответа>
- Приоритет: блокер / желательно / когда-нибудь
```

## Отложено (решение владельца)

## Категории trending-топиков ненадёжны
- **Что нужно:** надёжный маппинг категории для trending-топика, либо возможность фильтровать по категории на стороне парсера
- **Зачем:** `GET /trending` возвращает `categories: [3]` (Google ID), но Google присваивает их автоматически по своей логике и часто ошибается (например, Boeing 737 MAX = Entertainment)
- **Ответ агента парсера (2026-07-08):** корень не в парсере — категории присваивает Google, парсер их только ретранслирует, «улучшить» на его стороне нельзя. `category_label` (имя вместо ID) добавить легко, но это не чинит ошибочность (Boeing останется Entertainment, просто с именем). Настоящее решение — своя категоризация в discovery. **Владелец отложил:** пока категории берём как есть от Google; продуктовую категоризацию строим отдельным этапом позже. `category_label` сейчас не нужен.
