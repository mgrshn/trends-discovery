# Запросы к парсеру

Почтовый ящик между агентами. Агент discovery пишет сюда, что ему не хватает в API парсера.
Агент парсера читает и реализует; выполненные помечает и переносит в раздел «Выполнено».

Формат заявки:

```
## <краткий заголовок>
- Что нужно: <эндпоинт/поле/поведение>
- Зачем: <какая фича discovery без этого страдает>
- Предлагаемый контракт: <метод, путь, параметры, пример ответа>
- Приоритет: блокер / желательно / когда-нибудь
```

---

## Открытые

## Категории trending-топиков ненадёжны
- **Что нужно:** надёжный маппинг категории для trending-топика, либо возможность фильтровать по категории на стороне парсера
- **Зачем:** `GET /trending` возвращает `categories: [3]` (Google ID), но Google присваивает их автоматически по своей логике и часто ошибается (например, Boeing 737 MAX = Entertainment). Discovery не может улучшить эту классификацию без внешнего сигнала
- **Предлагаемый контракт:** либо добавить к каждому трендовому топику поле `category_label: str` (человекочитаемое название категории из Google), либо добавить параметр `?category=` к `/trending` с нормальной фильтрацией на стороне парсера (сейчас параметр есть, но эффективность неизвестна)
- **Приоритет:** желательно
