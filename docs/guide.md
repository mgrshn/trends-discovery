# Руководство по Trends Discovery

## Что это

Сервис мониторит Google Trends и находит темы, которые начинают набирать популярность — до того, как они стали мейнстримом. Пользователь видит дашборд с тремя вкладками: Real-time, Long-term и Live. Плюс инструмент ручного анализа любого ключевого слова.

Под капотом — два отдельных сервиса:
- **Discovery** (этот репозиторий) — хранит базу данных тем, считает скоры, отдаёт API для фронтенда
- **Parser** (`google-trends-parser`) — общается с Google Trends напрямую. Discovery никогда не идёт в Google сам — только через парсер по HTTP

---

## Три вкладки дашборда

### Real-time

Список тем, которые горят прямо сейчас — отсортированных по росту. Данные из **нашей базы**, обновляются каждый раз когда отработал авто-парсинг. При выключенном авто-парсинге данные могут быть часовой давности.

- Выбор страны через дропдаун (Worldwide недоступен — Google не поддерживает глобальный Trending Now)
- Сортировка: по объёму, росту, дате обнаружения, названию
- Фильтр «Active only» — только темы, обновлявшиеся за последние 48 часов
- Карточки показывают: ключевое слово, мини-график (спарклайн), объём поиска, % роста

### Long-term

Темы из нашей базы, которые прошли полный анализ (12-месячный тренд + скоринг). Показывает медленно нарастающие тренды — то, что начинает расти, но ещё не у всех на слуху.

- Доступен Worldwide (агрегат по всем странам)
- Фильтр по категориям Google (Health, Business, Technology и т.д.)
- Сортировка: по релевантности (скор), объёму, росту, дате скоринга
- У каждой темы есть **статус**:
  - **Exploding** — резкий рост прямо сейчас
  - **Regular** — устойчивый умеренный рост
  - **Peaked** — пик пройден, тема идёт на спад
  - **Noise** — недостаточно данных для вывода

### Live

Показывает что в тренде в Google **прямо сейчас** — без задержки нашего расписания. Данные идут напрямую от парсера, минуя нашу базу. Насколько свежо — настолько, насколько Google обновляет своё Trending Now (обычно лаг 20–40 минут).

- Выбор страны обязателен (Worldwide недоступен)
- Сортировка: по объёму, росту, названию
- Карточки показывают breakdown-запросы — подзапросы, из-за которых тема выстрелила
- Вкладка может быть включена/выключена в настройках (см. ниже)

**Разница между вкладками:**

| | Real-time | Long-term | Live |
|---|---|---|---|
| Источник данных | Наша БД | Наша БД | Парсер → Google |
| Свежесть | = последний ingest | До 7 дней | ~20–40 мин |
| Скор и статус | Нет | Есть | Нет |
| Спарклайн | Есть | Есть | Нет |
| Worldwide | Нет | Есть | Нет |
| Зависит от авто-парсинга | Да | Да | Нет (отдельная настройка) |

## Trend Analysis

Отдельная страница для глубокого анализа любого ключевого слова.

Вводишь слово, выбираешь страну и период (1 мес / 3 мес / 1 год / 5 лет) — и видишь:
- График интереса по времени
- Похожие запросы: **Rising** (резко растут) и **Top** (исторически популярные)
- Интерес по регионам

Первый анализ нового слова занимает 5–30 секунд — парсер запрашивает Google. Повторный анализ того же слова — мгновенно (парсер кеширует).

**Pre-warming** (если включён): как только Live-вкладка загрузила список тем или завершился ingest, сервис автоматически «прогревает» кеш парсера для топ-20 тем в фоне. За счёт этого клик «Analyze» на таких темах открывается значительно быстрее.

---

## Как данные попадают в базу

Весь процесс автоматический и идёт по цепочке:

**1. Ingest (каждые N минут)**
Для каждой выбранной страны — запрос к парсеру за топ-100 горячих тем. Темы сохраняются/обновляются в базе. После каждого ingest автоматически запускаются шаги 2 и 3.

**2. Спарклайны (после каждого ingest)**
Для топ-20 новых тем — запрос мини-графика (3-месячный тренд). Это то, что видно в карточках на дашборде.

**3. Скоринг (после ingest + каждый час)**
Для тем без оценки — запрос 12-месячного тренда. Дальше — чистая математика на нашей стороне (PHP), Google больше не нужен. Тема получает скор, статус (Exploding / Regular / Peaked / Noise) и цифры роста.

**4. Related Rising (каждые 6 часов)**
Берём топ-30 Exploding/Regular тем и для каждой ищем у парсера «похожие растущие запросы» — так находим новые темы в той же нише.

## Как считается скор

Скор — это число от 0 до ~100, которое показывает насколько тема «выстреливает». Считается полностью на нашей стороне по 12-месячному графику интереса из Google (52 точки).

Формула учитывает:
- **Крутизну роста** за последние 12 недель (главный фактор, вес 40%)
- **Ускорение** — ускоряется ли рост в последние 6 недель против предыдущих (10%)
- **Импульс** — насколько последние 4 недели горячее среднего за год (20%)
- **Объём поиска** — небольшой бонус популярным темам (10%)
- **Штраф за сезонность** — чтобы не путать «ёлочные игрушки в декабре» с настоящим трендом (−5%)
- **Штраф за хаотичность** — нас не интересуют темы, которые скачут без логики (−5%)

Статус определяется по отдельным правилам: падающий slope → Peaked, сильный рост с ускорением → Exploding, единичный вирусный всплеск (пик и спад) → не Exploding даже при высоком slope.

## Настройки (`/admin/parser-settings`)

### Авто-парсинг

**Enable auto-parsing** — главный рубильник. При выключении парсер не дёргается вообще — никаких автоматических запросов к Google. Ручные действия в Trend Analysis и кнопка «Parse now» продолжают работать.

**Parse interval** — как часто запускать ingest. Рекомендовано: 30 минут. При 51 стране один цикл ingest'а занимает несколько минут.

**Geos to parse** — галочки стран. Можно сузить список до нужных рынков — это ускоряет каждый ingest и снижает нагрузку. По умолчанию 51 страна.

### Live mode

**Live tab data source** — управляет вкладкой Live на дашборде:
- **Disabled** — вкладка не работает, показывает сообщение
- **On each request** — каждый запрос идёт напрямую к Google. Всегда свежо, но медленнее (5–30 секунд ожидания при холодном старте)
- **Cached** — первый запрос идёт к Google и результат кешируется на N минут. Все следующие запросы (от любых пользователей) в течение N минут — мгновенно

**Cache duration** — как долго хранить Live-данные в кеше (5 / 15 / 30 / 60 / 120 минут). Применяется только в режиме Cached.

**Pre-warm trend cache** — если включено, сразу после загрузки Live-вкладки (или после ingest) сервис в фоне запускает анализ топ-20 тем. Через 30–60 секунд клик «Analyze» на этих темах откроется мгновенно, а не за 5–30 секунд. Можно выключить, если нужно снизить нагрузку на парсер.

### Кнопки

**Parse now** — разовый немедленный ingest. Можно выбрать конкретные страны или оставить пустым (запустится по всем выбранным в настройках).

**Recalculate scores** — запустить скоринг прямо сейчас для 100 неоценённых тем. Полезно при первичном наполнении базы или после долгого простоя.

**Save settings** — сохранить все изменения на странице.

## Мониторинг (`/admin/jobs-monitor`)

Главная страница для проверки что всё работает.

**Статус парсера** — зелёный/красный индикатор. Проверяется при каждом открытии страницы. Если красный — парсер недоступен, данные не обновляются.

**Счётчики:**
- **Pending jobs** — задачи в очереди, ждут обработки
- **Failed jobs** — задачи, которые упали после всех попыток
- **Scored today** — тем получили скор сегодня
- **Topics total / scored** — сколько всего тем и сколько из них оценены

**Pending jobs** (таблица) — показывает очередь: какие задачи скоро запустятся. Там можно увидеть IngestTrendingJob, SparklineFetchJob, ScoreTopicsJob и т.д.

**Failed jobs** — упавшие задачи. Можно посмотреть ошибку, перезапустить отдельную или все сразу, удалить.

Ссылка **Open Horizon dashboard** → `/horizon` — детальная статистика: throughput очередей, время выполнения задач, история за последние часы.

---

## Прокси (`/admin/proxies`)

Прокси нужны парсеру, чтобы не получить бан от Google при частых запросах. Хранятся в самом парсере, мы управляем ими через его API.

На странице: список прокси с хостом, протоколом, статистикой успехов/отказов. Можно:
- Добавить прокси в формате `http://user:pass@host:port` или `socks5://host:port`
- Включить / отключить
- Проверить — парсер попробует выйти через прокси и вернёт результат (OK/Failed, задержку, внешний IP)
- Удалить

**Важно:** после любых изменений надо перезагрузить воркер парсера командой:
```bash
docker compose kill -s HUP parser-worker-1
```
Об этом напоминает всплывающее уведомление после каждого действия.

## Healthcheck

`GET /api/health` — быстрая проверка состояния сервиса. Возвращает JSON:

```json
{
  "status": "ok",
  "service": "trends-discovery",
  "parser": { "url": "http://parser:8000", "reachable": true }
}
```

Если парсер недоступен — HTTP 503 и `"status": "degraded"`. Можно подключить к любому uptime-мониторингу.

## Первый запуск

1. Контейнер backend поднялся → автоматически применил миграции, засеял категории, закешировал конфиг
2. Включи **Enable auto-parsing** в Parser Settings (или нажми **Parse now**)
3. Первый ingest по 51 стране соберёт до 5100 тем
4. Параллельно начнут приходить спарклайны и первые скоры
5. Каждый час добавляются ещё 100 оценённых тем — при базе 14 000 тем полный скоринг займёт ~5–6 дней

Если нужно ускорить скоринг — нажимай **Recalculate scores** вручную, каждый клик добавляет 100 тем в очередь.

## Что делать если что-то сломалось

| Симптом | Что проверить | Как починить |
|---------|--------------|--------------|
| Данные не обновляются | Jobs Monitor → статус парсера | Если красный — проверь docker, прокси |
| Failed jobs копятся | Jobs Monitor → список ошибок | Retry all / исправить причину |
| Парсер красный, но docker работает | Парсер внутренняя ошибка | `docker logs parser-worker-1` |
| Live вкладка не работает | Parser Settings → Live mode | Включить, выбрать режим, сохранить |
| Analyze открывается медленно | Нормально при первом запросе | Включить Pre-warm — ускорит повторные |
| Прокси все отвалились | Proxies → Check каждый | Добавить рабочие прокси, HUP воркер |

Docker перезапускает все упавшие контейнеры автоматически (`restart: unless-stopped`). Задачи в очереди — Horizon ретраит их автоматически (3 попытки для ingest, 2 для scoring).
