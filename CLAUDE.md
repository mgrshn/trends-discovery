# CLAUDE.md — trends-discovery

Discovery-сервис поверх парсера Google Trends: функциональная копия Exploding Topics Pro
(https://www.semrush.com/app/exploding-topics/pro/dashboard). Заказчик визуально сравнивает
каждую страницу с оригиналом.

## Перед любой работой прочитай

1. `DISCOVERY_PLAN.md` (этот репо) — полное ТЗ: контекст, ограничения, схема БД, этапы с критериями приёмки
2. `docs/decisions.md` — принятые архитектурные решения (не пересматривать без причины)
3. `/Users/mgr/Projects/SMH/google-trends-parser/CLAUDE.md` — архитектура парсера-соседа
4. Живой контракт парсера: `curl http://localhost:8000/openapi.json` (Swagger: http://localhost:8000/docs)

## Веди журнал СРАЗУ, по ходу работы (не откладывай на конец)

Как только возникает решение, вопрос или нехватка — фиксируй немедленно, в момент возникновения.
Отложенное логирование = потерянный контекст. Это обязательная часть работы, а не финальная формальность.

- `PARSER_REQUESTS.md` — **любой вопрос/нехватка к парсеру**: не хватает эндпоинта, поля, неясно
  поведение API. Формат: что нужно / зачем / предлагаемый контракт / приоритет. Записал — и продолжай,
  НЕ блокируйся: почти всё решается на стороне discovery. Эти заявки обслуживает агент парсера.
- `docs/decisions.md` — **любое архитектурное решение** (формат: дата · решение · почему) И
  **любой открытый вопрос к владельцу**, который ты не можешь решить сам (помечай `ОТКРЫТЫЙ ВОПРОС:`).
  Не молчи о развилках — выписывай их, чтобы владелец увидел и ответил.
- `DISCOVERY_PLAN.md` — отмечай завершённые этапы по мере готовности.

## Связь с парсером (границы сервисов)

- Парсер: `/Users/mgr/Projects/SMH/google-trends-parser`, работает на `http://localhost:8000`
- **Код парсера НЕ менять.** Его обслуживает другой агент
- Общение ТОЛЬКО по HTTP: env `PARSER_URL` + заголовок `X-API-Key` из env `PARSER_API_KEY`.
  Никаких подключений к его PostgreSQL/Redis
- ЧИТАТЬ его репозиторий можно и нужно — форматы данных, паттерны кода, конвенции
- Не хватает чего-то в API парсера → записать в `PARSER_REQUESTS.md`
  (формат: что нужно / зачем / предлагаемый контракт) и продолжать работу, не блокируясь

## Стек

- **Backend: Laravel 13** (или макс. под текущий стабильный Filament — проверить при старте) + PostgreSQL.
  Очереди/планировщик — Laravel Scheduler + Horizon. Бизнес-логика — в сервис-слое (не в контроллерах/Livewire).
- **Filament** — внутренняя админка/курация, `/admin`. Подключить рано и минимально.
- **Frontend: отдельная React SPA** — Vite + TypeScript + Tailwind + ApexCharts. Ходит только в API бэкенда.
  Шрифт Manrope. Язык UI — английский (копия оригинала).
- **Скоринг — на PHP**; тяжёлую статистику при необходимости выносить в отдельный Python-сервис за HTTP.
- **Вебсокеты — не в MVP**; позже Laravel Reverb + Echo.
- Разведка UX оригинала — в `docs/ux/` (скриншоты + разбор страниц + категории с числами).

Парсер (Python) — чёрный ящик за HTTP, его стек нас не касается. Без авторизации в продуктовой части,
но `user_id BIGINT NULL` в продуктовых таблицах и все API-роуты в одной route-группе — с первого дня.
